description: The international standard for card transaction messages exchanged between acquirers and issuers.
---

ISO 8583 is the international standard for the messages that card systems exchange, such as authorization requests and responses. It defines a common interface between [acquirers](./Acquirer.md) and [issuers](./Issuer.md), usually through a [card network](./Card%20network.md). The current edition is ISO 8583:2023. Older editions remain in production.

An ISO 8583 message has three main parts.

| Part                  | Purpose                                       | Example                     |
| --------------------- | --------------------------------------------- | --------------------------- |
| Message type indicator | Says what the message is                     | `0100` authorization request |
| Bitmap                | Marks which data fields are present           | Bits for fields 2, 3, 4     |
| Data elements         | Carry the values                              | [PAN](./PAN.md), amount, response code |

Mastercard's rules show how these labels appear in practice.

| Message | Meaning                         |
| ------- | ------------------------------- |
| `0100`  | Authorization request           |
| `0110`  | Authorization response          |
| `0400`  | Reversal request                |
| `0420`  | Acquirer reversal advice        |
| `1240`  | First presentment, for [clearing](./Clearing.md) |

The standard is a framework, and each network implements its own variant. Field usage, private data elements and code values differ between Visa, Mastercard and domestic switches. A parser built from the ISO document alone will not correctly handle a real network feed, so work from the network or processor's interface specification.

Most application developers never see ISO 8583 because a [payment service provider](./Payment%20service%20provider.md) wraps it in a JSON API. It still shapes what they receive. A [decline code](./Decline%20code.md) such as `51` comes from a response code field, and a truncated [statement descriptor](./Statement%20descriptor.md) reflects a fixed-length name field.

Engineers working closer to the rails meet different failures: a bitmap that does not match the fields sent, an amount in the wrong [minor unit](./Minor%20unit.md), or a reversal that omits the original transaction's reference data. Log parsed messages with the PAN and other sensitive fields masked, since raw dumps bring logs into [PCI DSS](./PCI%20DSS.md) scope.

ISO 8583 is separate from [ISO 20022](./ISO%2020022.md), the data standard widely used for bank payments.

_Usage:_

"The processor rejected our message but the JSON looks fine."
